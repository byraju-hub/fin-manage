## ① 내려받기 사유

**지금**: 장부·결산 CSV(`/export/*`), 영수증 발급명세 CSV(`/receipts-export`), 백업(`/backup/download`)은 내려받을 때 "누가 언제 무엇을"만 기록합니다. 사유는 없습니다.

**설계**
- 내려받기 단추를 누르면 작은 창이 뜹니다: **사유 선택**(세무 신고 / 감사 제출 / 결산 보고 / 백업 보관 / 기타(직접 입력)) → 확인.
- 서버는 1회용 짧은 열쇠(60초, 서명된 값. 표 추가 없음)를 주고, 화면이 그 열쇠로 파일 주소를 엽니다. 열쇠 없이 파일 주소를 직접 열면 거절됩니다. (일반 링크는 사유를 담을 곳이 없어서 이 방식이 필요)
- 사유는 접속 기록의 대상 칸에 `영수증 발급명세 2026 · 사유: 세무 신고` 처럼 남습니다. (IP는 이미 기록됨)
- 안내 문구: "내려받은 파일은 쓰고 나서 지워 주세요."
- 체험 계정은 지금처럼 내려받기 자체가 막힘.

**정할 것**
1. 사유를 **필수**로 할지(★ 영수증 발급명세·백업만 필수, 장부·결산은 개인 이름이 없어 사유는 선택) / 모두 필수 / 전부 선택
2. 사유 선택지 목록(위 5개로 충분한지)

**시험**: 열쇠 없이 직접 열면 403, 열쇠는 한 번만·60초, 사유가 기록에 남음, 사유 필수 항목에 사유 없이 요청하면 422.

## ② 개인정보 동의 확인

**배경**: 교적에는 동의 기록 표(`cm_consents`: 교적 등록·민감정보·요람 공개·보호자 동의, 처리방침 판, 날짜, 방법, 철회일)가 이미 있습니다. 재정은 **읽기만** 해야 합니다(약속). 개인별 헌금은 민감정보에 준해 다루므로, 헌금자 동의 상태를 볼 수 있어야 합니다.

**설계 (A: 교인 헌금자 — 읽기)**
- 영수증 › 헌금자 목록에 **동의 배지**: `동의 있음(판 2026-11-25)` / `동의 없음` / `철회됨` / `14세 미만·보호자 동의 필요`. 판이 오래되었으면 `이전 판`.
- 영수증 발급 전 미리보기에서 동의가 없는 사람에게 **경고 표시**(★ 막지는 않음, 교적 담당자에게 확인 요청 안내). 막을지는 아래 질문.
- 처리방침 판 값은 지금 `privacy` 화면 안에만 있어서, **한 곳(공용 상수)** 으로 옮겨 방침 화면·동의 비교가 같은 값을 쓰게 함.
- 교적에서 동의를 만드는 일은 하지 않음(교적 담당자가 함).

**설계 (B: 교인이 아닌 헌금자 — 재정이 직접 기록, 선택)**
- 교적에 없는 외부인·단체 헌금자는 교적 동의가 없으므로, 재정에 작은 표 `fm_donor_consents`(헌금자, 처리방침 판, 동의일, 방법(서면·구두·앱), 철회일, 메모)를 추가(마이그레이션 006). 주민등록번호를 받는 사람은 **수집·이용 동의 기록**을 남기게 함.
- 헌금자 화면에서 "동의 기록"을 한 줄로 남기고, 철회하면 번호 삭제를 안내.

**정할 것**
1. 동의가 없는 헌금자의 영수증 발급: ★경고만 / 발급 막기 / 아무것도 안 함
2. B(비교인 동의 기록 표)를 지금 만들지: ★만든다 / 나중에
3. 동의 배지를 **주민번호를 받는 사람에게만** 강조할지(★ 모두 표시, 주민번호 있는 사람은 빨간색)

**시험**: 교적 동의 유무·철회·14세 미만에 따라 배지가 맞게 나옴, 교적에 아무것도 쓰지 않음(읽기 전용), 체험 모드는 가짜 상태.

## ③ 영수증 기간(월·분기) 조회

**지금**: 영수증 대상 합계는 과세 **연도 단위**로만 봅니다. (내부 계산은 월별로 이미 나눠져 있음 — `receipt_groups`)

**설계 — 1단계(★ 먼저, 조회·인쇄만)**
- 영수증 화면 미리보기에 **기간 선택**: 연간 / 1~4분기 / 월 선택 / 직접(시작월~끝월).
- 표에 월별 칸을 보여 주고, **"참고용 합계(영수증 아님)"** 로 인쇄 가능. 헌금자에게 "분기 헌금 내역 안내"를 줄 때 씀.
- 발급은 **지금처럼 연도 단위**만. 기간 합계는 발급 대장에 들어가지 않음.
- 비용: 화면과 조회 API 하나(DB 변경 없음).

**설계 — 2단계(보류 권장, 기간 발급)**
- 발급 대장에 기간(`period_from`, `period_to`)을 넣고 분기·월 단위 영수증 발급을 허용(마이그레이션 006).
- 위험: 같은 헌금이 연간 영수증과 분기 영수증에 **이중으로** 들어가면 안 됨 → 겹침 검사 필요. 세무상 영수증은 연 단위가 일반적이라 세무 담당자 확인이 먼저.

**정할 것**
1. ★1단계만 / 1·2단계 모두 / 하지 않음
2. 분기 기준: ★1~3월, 4~6월… (달력) / 회계연도 시작 월 기준

**시험**: 기간 합계가 마감된 헌금과 맞음, 분기 합이 연간 합과 같음, 발급은 기간과 무관하게 연도 단위로 동작.

## ④ 세대주 맞춤

**지금**: 영수증 합산(가족 대표 한 명 명의로 모아 발급)은 `receipt_to_donor_id`로 **사람이 정합니다.** 교적에서 세대주가 바뀌거나 가족이 이사·분가해도 재정의 합산은 그대로여서, 어긋날 수 있습니다. (합산 제안 `/donors/{id}/household`는 있음)

**설계**
- 영수증 › 헌금자 탭 위에 **"세대 확인"** 카드: 교적과 비교해 어긋난 합산을 목록으로 보여 줌.
  - 합산 대표가 이제 그 세대의 세대주(교적 `household_members.relation = '본인'`)가 아님
  - 합산 대상이 다른 세대로 옮겨 감 / 교적에서 삭제·정리됨
  - 같은 세대인데 합산이 안 된 헌금자(제안)
- 줄마다 **[맞추기]**(세대주를 새 대표로) / **[그대로]**(이 건은 알림 끄기). 자동으로 바꾸지 않음.
- 이미 그 해 영수증이 **발급된 대표**를 바꾸면 "정정 발급이 필요하다"는 안내를 함께 보여 줌(기존 정정 흐름 사용).
- 바꾼 내용은 변경 기록에 남음. 교적은 읽기만.

**정할 것**
1. 대표 기준: ★기본은 세대주지만 사람이 다르게 정한 합산은 존중(알림만) / 항상 세대주로 강제
2. "그대로"로 끈 알림을 다시 켜는 시점: ★다음 해 영수증 때 다시 / 영구

**시험**: 세대주 변경 시 어긋남이 나옴, 맞추기 후 합산이 바뀌고 발급 정정 안내가 나옴, 교적 표는 변하지 않음.

## ⑤ 교구별 합계

**배경**: 교적의 소그룹(`cm_small_groups`, 장년만 소속 `cm_person_groups`)과 공동체(`cm_communities`)가 있고, 이름은 교회가 정함(교구·구역·목장 등). 재정은 지금 이 표들을 읽지 않으므로 **읽기 대상에 표 3개를 추가**해야 합니다(`FM_CM_REQUIRED`).

**설계**
- 보고서 › **교구(소그룹)별 헌금**: 기간(월~월)·헌금 종류를 고르면 교구별 **합계·인원·1인 평균**. 개인별 금액은 보이지 않음.
- 헌금자가 교인이고 교적 소그룹에 소속되어 있을 때만 집계. 소속이 없거나 교인이 아니면 `소속 없음`에 합산.
- **작은 모임 보호**: 교구 안 헌금자가 **N명 미만**(★ 3명)이면 이름 대신 `기타(소규모)`로 합쳐 보여 줌 — 인원이 적으면 합계로 개인 헌금을 알 수 있기 때문.
- 권한: 재정 담당·재정위원장·담임목사·감사 / 개인별 헌금 열람 지정자만(합계 보고라 열람 역할은 제외). 열 때 접속 기록.
- 체험 모드: 가짜 교구(가짜 헌금자에 가짜 교구 이름을 붙임).
- 교적이 오래된 버전이면(표 없음) 메뉴를 숨기고 "교적을 올리면 쓸 수 있어요" 안내.

**정할 것**
1. 최소 인원 N: ★3명 / 5명 / 보호 안 함
2. 기준을 소그룹으로만 할지, **공동체(장년·청년 등) 단위 합계**도 함께 볼지(★ 소그룹만, 공동체는 나중)
3. 교구 이름: 교적의 `site_settings`에 있는 이름(교구/구역/목장)을 그대로 쓸지(★ 예)

**시험**: 교구별 합이 전체 마감 합과 맞음(소속 없음 포함), N 미만 모임이 합쳐짐, 권한 없는 역할 403, 교적 표를 쓰지 않음.

## 공통 사항
- 모든 새 화면은 **체험 모드에서 가짜 자료**로 보이고 보기 전용.
- 새 표는 마이그레이션 006 하나로 모음(② B만). 나머지는 DB 변경 없음.

- 각 항목은 시험 파일(`m14_…`)을 함께 만들고, 기존 시험이 모두 통과해야 배포.
