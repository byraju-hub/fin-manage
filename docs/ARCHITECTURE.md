# fin-manage 구조 설계 (v0.3 초안)

> 교회 재정 관리 시스템. 교적 관리 [ch-manage](https://github.com/byraju-hub/ch-manage)(`cm_`), 부서 관리 [dep-manage](https://github.com/byraju-hub/dep-manage)(`dm_`)와 같은 호스팅 계정·같은 DB 에서 함께 쓴다. 표 접두어는 `fm_`.
> 작성일: 2026-11-10 · 상태: 설계 초안 (코드 없음).
> **v0.3 (2026-11-10) 반영한 결정**: ① 담임목사 결재 단계·금액별 전결 필요 ② 개인별 헌금은 담임목사와 지정한 감사가 열람 ③ 주민등록번호는 교회가 설치 때 선택(암호화 보관 / 미보관) ④ **교적과 통합 로그인** — 교적 계정으로 로그인하고, 재정 사용을 승인받은 사람만 쓴다. ⑤ 결재 구간의 금액 기준과 직접 지출 범위는 **관리자가 설정 화면에서 입력·지정**. 남은 결정은 15장. **화면 시안은 `design/` 폴더 (index.html 부터 열기).**

## 1. 목표와 원칙

| 원칙 | 내용 |
|---|---|
| 같은 방식 | 정적 화면(SvelteKit) + PHP API + MariaDB, 설치 마법사(`/install/`), 서브폴더 설치(`/fm/`). 카페24 최저가 호스팅 기준 |
| 교적이 사람의 주인 | 교인의 이름·연락처·주소·세대, 조직표(위원회·부서)는 교적에서 읽기만 한다. 재정은 `cm_` 표에 **쓰지 않는다** |
| 돈의 기록은 지우지 않는다 | 삭제 대신 취소(사유 기록), 마감한 기간은 정정 전표로만 고친다. 누가 언제 무엇을 바꿨는지 전부 남긴다 |
| 헌금 내역은 가장 민감한 정보 | 개인별 헌금은 별도 권한이 있어야 보이고, 열람할 때마다 기록한다. 권한이 없는 자료는 서버가 내려보내지 않는다 |
| 한 사람이 처음부터 끝까지 못 한다 | 기안·결재·지급을 나눈다. 자기 기안을 혼자 결재해 끝낼 수 없다 |
| 서버가 정한다 | 권한, 결재 순서, 금액 합계, 발급 번호, 쓴 사람과 시간은 서버가 계산한다. 화면이 보낸 값은 믿지 않는다 |

### 범위

- **v1 에 넣는 것**: 헌금 입력(개인별), 기타 수입, 예산, 지출결의서와 전자결재, 지급 처리, 장부(현금·통장), 재정 보고, 기부금 영수증, 마감·결산·이월, 백업
- **넣지 않는 것**: 복식부기(자산·부채 계정), 급여·4대보험 계산, 은행 자동 연결, 카드사 연동. 단식부기(수입·지출부) + 계좌별 잔액으로 간다. 대부분의 교회 결산서가 이 방식이다

## 2. 전체 구조

```
[브라우저]  Svelte SPA (빌드된 정적 파일)   /fm/
    │  fetch /fm/api/v1/...   세션 쿠키(fm_sid) + X-CSRF-Token
    ▼
[PHP 8.x]   api/index.php → 라우터 → 컨트롤러 → PDO
    │
    ▼
[MariaDB]   fm_*  (쓰기)        ← 재정 자료
            cm_*  (읽기만)      ← 교인·세대·조직표·교회 정보
```

- 저장소 구조·설치 마법사·마이그레이션(`server/migrations/001_init.php …`)·릴리스 zip·보안 헤더·`data/` 보호는 ch-manage 와 같게 한다
- **자료를 읽고 쓰는 방식은 dep-manage 식(화면마다 필요한 것만 요청)** 으로 한다. ch-manage 의 "전부 받아 두고 바뀐 칸만 보내기(`bootstrap`/`sync`)"는 쓰지 않는다

| 이유 | 설명 |
|---|---|
| 자료가 많다 | 헌금은 교인 300명만 되어도 한 해 수만 줄이다. 전부 내려받을 수 없다 |
| 사람마다 볼 수 있는 범위가 다르다 | 부서 회계는 자기 부서 지출만, 개인별 헌금은 권한자만. 줄 단위로 서버가 걸러야 한다 |
| 결재는 상태 변화다 | "결재한다·반려한다·지급한다"는 칸을 고치는 것이 아니라 서버가 조건을 확인하고 실행하는 동작이다 |
| 합계는 서버에서 | 예산 대비 집행액, 계좌 잔액, 영수증 금액은 SQL 로 합산한다 |

다만 이름 검색이 빨라야 하므로 **교인 찾기용 가벼운 목록**(id·이름·동명이인 표시·출생 연도·소그룹·재적 상태)은 로그인 때 한 번 받아 메모리에 둔다.

### 호스팅 제약 (ch-manage 에서 확인한 것을 그대로 적용)

- 요청 본문 128KB 한도 → 영수증 사진은 화면에서 줄여(긴 변 1600px, JPEG) 60KB 조각으로 올린다. 헌금 일괄 저장도 100KB 이하로 나눈다
- 예약 작업(cron) 없음 → 자동 백업은 화면이 1분마다 부르는 `/version` 응답 뒤에 실행한다
- 파일은 `data/` 한 곳에만 두고 PHP 가 권한을 확인한 뒤 내려준다

## 3. 교적(ch-manage)과의 관계

**재정은 교적이 같은 DB 에 설치되어 있어야 동작한다.** (교적·부서 관리는 서로 없어도 되지만, 재정은 교인 목록이 없으면 의미가 없다.)
설치 마법사와 API 가 `cm_people`·`cm_org_units` 등 필요한 표와 열이 있는지 확인하고(접두어는 `data/config.php` 의 `cm_prefix`, 기본 `cm_`), 없으면 설치를 멈추고 안내한다.

### 3.1 무엇을 읽는가

| 교적의 표 | 재정에서 쓰는 곳 |
|---|---|
| `cm_people` (+ `cm_status_events`, `cm_person_groups`) | 헌금자 찾기, 담당자(회계·부서장·위원장) 선택, 사용자 계정과 연결 |
| `cm_households`, `cm_household_members` | 기부금 영수증의 주소, 가족 합산 발급 제안 |
| `cm_org_units` (위원회 > 부서, `leader_id` = 위원장·부서장) | 해마다 재정 단위(예산 편성 단위)를 만들 때 가져오기 |
| `cm_site_settings.church_info` (교회 이름·고유번호·주소·대표자) | 영수증·보고서 머리글. 직인 그림은 재정 쪽에 따로 올린다(두 프로그램의 `data/` 가 다르므로) |
| `cm_users` (아이디·비밀번호 해시·상태·`person_id`·`session_epoch`·`is_demo`) | **로그인 확인** (4.1). 비밀번호 해시를 읽어 대조만 하고 재정은 이 표를 고치지 않는다 |

### 3.2 연결하는 방법

- 재정의 표는 교인을 `person_id CHAR(36)`(= `cm_people.id`)로 가리킨다. **외래키는 걸지 않는다.**
  - 교적에서 교인을 지우거나, 개인정보 정리(전출·별세 N년 뒤)를 하거나, 백업을 되살릴 때 재정 기록 때문에 막히거나 재정 기록이 함께 지워지면 안 된다
- 그래서 재정 쪽에 **이름을 함께 적어 둔다(스냅숏)**. 헌금자(`fm_donors.name`), 결재자(`fm_approval_steps.approver_name`), 재정 단위(`fm_units.name`) 모두 마찬가지. 교적에서 사람·부서가 사라져도 장부와 영수증 대장은 그대로 읽힌다
- 화면에는 지금의 교적 이름을 우선 보여 주고, 교적에 없으면 적어 둔 이름에 "교적에 없음" 표시를 붙인다
- 교적에서 이름이 바뀌면(개명) 재정 화면의 '교적과 맞추기'에서 미리보기 후 스냅숏을 고친다. 이미 발급한 영수증은 발급 당시 이름 그대로 둔다

### 3.3 항목별 주인

| 항목 | 주인 |
|---|---|
| 이름·생년월일·연락처·주소·세대 | 교적 |
| 조직표의 위원회·부서 이름과 구조, 위원장·부서장(현재) | 교적 |
| **그 해의** 재정 단위·예산·결재 담당자(회계·부서장·위원장·재정위원장) | 재정 (교적에서 가져와 해마다 확정) |
| 헌금·수입·지출·결재·영수증 | 재정 |
| 주민등록번호(영수증용), 헌금자 번호 | 재정 (교적에는 두지 않는다는 기존 방침 유지) |

조직표를 그대로 읽지 않고 **해마다 복사해 두는 이유**: 교적의 조직표는 "지금" 한 벌뿐이고 부서를 지우면 사라진다. 예산과 결산은 "2026년의 교육위원회 유치부"라는 그 해의 단위에 묶여야 작년 결산이 올해 조직 개편에 흔들리지 않는다.

### 3.4 교적 쪽에서 바뀌는 것 (작게, 나중에)

- 교적 '문서 › 기부금 영수증'은 지금 금액을 손으로 적는다. 재정이 설치되어 있으면 이 문서를 재정의 영수증 발급으로 안내한다(교적 사용자에게 헌금 금액을 보여 주지 않기 위해 금액을 끌어오지는 않는다)
- 교적 카드에 헌금 정보는 **표시하지 않는다**
- **통합 로그인을 위한 교적 쪽 작은 추가 (M1-b, 선택)**: 교적 화면에 '재정 열기' 버튼. 누르면 교적이 1회용 입장권을 만들고(`cm_sso_tickets`: 무작위 값의 해시, 사용자, 30초 유효, 마이그레이션 007) `/fm/sso?t=…` 로 보낸다. 재정이 입장권을 확인하고 **지운 뒤**(재정이 교적 표에 쓰는 유일한 경우) 자기 세션을 만든다. 이 추가가 없어도 재정 로그인 화면에서 같은 아이디·비밀번호로 들어갈 수 있다(4.1)
- 교적 사용 환경: 교적의 구조 버전이 재정이 요구하는 번호 이상이어야 한다(설치 때와 `/system/status` 에서 확인)
- 발급 번호: 재정이 자체 번호(`fm_meta.receipt_seq_<연도>`)를 쓴다. 교적의 증명서 대장(`cm_certificates`)과 섞지 않는다

## 4. 로그인과 권한

### 4.1 계정: 교적과 통합 로그인 + 재정 사용 승인

**계정의 주인은 교적(`cm_users`)이다.** 재정에는 비밀번호도 가입 화면도 없다. 대신 "이 교적 계정이 재정을 써도 되는가"를 `fm_access` 한 표로 관리한다.

```
교적에서 가입·승인 (cm_users, 교인과 연결)
        │ 같은 아이디·비밀번호
        ▼
재정 로그인 ─ cm_users 로 확인 ─▶ fm_access 가 '사용' 인가?
                                     ├ 사용 → 재정 세션(fm_sid) 시작, 역할대로 메뉴
                                     ├ 신청 대기 → "승인 대기 중" 화면만
                                     └ 없음 → "재정 사용 신청" 버튼 (한 번 누르면 신청 대기)
```

| 항목 | 방식 |
|---|---|
| 로그인 확인 | `cm_users` 의 `password_hash` 를 읽어 `password_verify`. 교적 계정이 `사용` 상태이고 체험 계정(`is_demo`)이 아닐 때만. 교적에서 정지하면 재정도 바로 막힌다 |
| 세션 | 재정은 **자기 세션**(쿠키 `fm_sid`, 경로 `/fm`, 세션 파일은 재정 `data/sessions`)을 만든다. 두 프로그램의 쿠키 경로·세션 폴더가 서로 달라 세션을 직접 나눠 쓸 수 없기 때문이다 |
| 한 번에 들어가기 | 교적 화면의 '재정 열기'(3.4의 입장권) 또는 재정 로그인 화면에서 같은 아이디·비밀번호 |
| 비밀번호 바꾸기·임시 비밀번호 | **교적에서만** 한다(재정 화면에는 '교적에서 바꾸기' 안내). 바꾸면 `cm_users.session_epoch` 가 올라가고, 재정은 세션에 적어 둔 값과 요청마다 비교해 다른 기기의 재정 세션도 끊는다 |
| 재정 사용 승인 | `fm_access`(`cm_user_id`, `login_id` 스냅숏, `status`: 신청 대기·사용·정지, `is_admin`, 개인별 헌금 열람 스위치, 신청·승인 시각, 승인자). **재정 관리자**가 승인하고 시스템 역할(4.2)을 준다 |
| 교인 연결 | `cm_users.person_id`(교적에서 교인과 연결한 값)를 쓴다. 비어 있으면 재정 사용을 승인할 수 없고 "교적에서 이 계정을 교인과 연결하세요"라고 알린다(조직 역할·결재선이 교인 단위이므로) |
| 첫 재정 관리자 | 설치 마법사에서 **교적 최고관리자**(`is_super`)의 아이디·비밀번호로 확인하고 `fm_access`(`is_admin`) 로 등록. 교적 최고관리자라고 해서 자동으로 재정 권한이 생기지는 않는다 |
| 로그인 시도 제한 | 재정 쪽에도 따로 둔다(`fm_login_attempts`, 같은 아이디·같은 주소 15분). 교적 표는 건드리지 않는다 |
| 접속 기록 | 이름은 교적에서 읽은 값을 스냅숏으로 적는다 |

- **교적을 쓰는 사람 ≠ 재정을 쓰는 사람**: 교적에 로그인되는 교역자·교적 담당자·소그룹 인도자(D 등급)도 재정 사용 승인이 없으면 재정에는 아무것도 보이지 않는다. 계정은 하나지만 권한은 나뉜다
- 교적 계정이 삭제되면(`cm_user_id` 가 사라지면) `login_id` 스냅숏으로 다시 짝을 찾고, 못 찾으면 '끊어진 계정'으로 알려 사용을 막는다. 교적 백업을 되살려 사용자 번호가 바뀌어도 아이디로 다시 이어진다
- 보안 기본은 교적과 같다: CSRF + Origin 검사, 30분 세션, 비밀번호 해시는 응답에 절대 넣지 않는다
- **결재·지급·영수증 발급·마감** 같은 중요한 동작은 비밀번호를 다시 묻는다(설정으로 켜고 끔, 기본 켬). 교적 비밀번호와 같은 값이며, 이것이 전자결재의 본인 확인이다

### 4.2 두 가지 권한

**(1) 시스템 역할** — 계정에 붙는다 (`fm_user_roles`, 한 사람이 여러 개 가능)

| 역할 | 누구 | 할 수 있는 일 |
|---|---|---|
| 재정 관리자 | 설치한 사람 | 재정 사용 승인·역할 지정, 설정, 백업·되살리기. 재정 업무 권한은 따로 받아야 한다 |
| 재정 담당 | 재정부 회계·서기·간사 | 헌금 입력·마감, 수입·지출 등록, 지급 처리, 예산 입력, 보고서, 영수증 발급 |
| 재정위원장 | 재정위원장 | 결재, 예산 확정, 월·연 마감 승인, 모든 보고서 |
| **담임목사** | 담임목사 | 결재선의 담임목사 단계(8.3), 모든 장부·결의서·보고서 열람, **개인별 헌금 열람(기본 켬)** |
| 계수 위원 | 헌금 계수 봉사자 | 자기가 맡은 날의 헌금 입력만. 마감하면 더 볼 수 없다 |
| 감사 | 감사 | 모든 장부·결의서·기록 열람(읽기 전용) |
| 열람 | 당회원 등 | 보고서(합계) 열람 |

별도 스위치 **개인별 헌금 열람**(`fm_access.can_view_donors`): 재정 담당·재정위원장·담임목사는 기본 켬, **감사는 재정 관리자가 "지정한 감사"에게만 켠다**(기본 끔), 열람 역할은 켤 수 없다. 지정과 해제는 수정 기록에 남고, 개인별 헌금을 열 때마다 접속 기록이 남는다.

**(2) 조직 역할** — 사람(`person_id`)에 붙는다 (`fm_unit_roles`, 연도·재정 단위별)

| 역할 | 할 수 있는 일 |
|---|---|
| 부서 회계 | 그 부서의 지출결의서 기안, 그 부서 예산·집행 현황 열람 |
| 부서장 | 그 부서 결의서 1차 결재, 부서 현황 열람 |
| 위원장 | 소속 부서들의 결의서 2차 결재, 위원회 현황 열람 |

- 담당자는 교인 목록에서 검색해 지정한다. **계정이 아직 없는 교인도 지정할 수 있고**, 그 사람이 가입해 교인과 연결되면 그때부터 권한이 생긴다
- 부서장·위원장의 기본값은 교적 조직표의 `leader_id`. 재정에서 다르게 지정할 수 있고, 교적과 다르면 '교적 조직표와 다름'으로 알려 준다
- 시스템 역할이 하나도 없어도 조직 역할이 있으면 로그인해서 자기 부서 일만 한다
- 부서 회계는 헌금·다른 부서의 지출을 볼 수 없다. 서버는 범위 밖의 결의서를 "없음(404)"으로 답한다

## 5. 재정 분류

### 5.1 회계연도와 회계

- **회계연도**(`fm_fiscal_years`): 시작 월을 설정으로(1월 또는 12월 시작 교회가 있음). 상태는 편성 중 → 진행 → 마감
- **회계**(`fm_funds`): 기본은 '일반회계' 하나. 건축·선교·장학처럼 따로 관리하는 돈이 있으면 특별회계를 추가한다. 수입 항목마다 들어갈 회계를 정한다(예: 건축헌금 → 건축회계). 이월금·잔액·결산은 회계별로 낸다
- **계좌**(`fm_wallets`): 현금, 통장들. 모든 수입·지출은 어느 계좌의 돈인지 적는다. 계좌 사이 옮김은 '이체' 거래

### 5.2 수입 항목 (`fm_income_accounts`, 최대 3단계, 교회가 고칠 수 있음)

```
수입
├─ 헌금
│   ├─ 십일조
│   ├─ 감사헌금
│   ├─ 주일헌금
│   ├─ 건축헌금
│   ├─ 선교헌금
│   ├─ 구제헌금
│   ├─ 절기헌금 ─ 신년 · 부활 · 맥추감사 · 추수감사 · 성탄
│   ├─ 총회헌금
│   ├─ 부서헌금        (입력할 때 어느 부서인지 재정 단위를 함께 고름)
│   ├─ 목적헌금        (입력할 때 목적을 적음)
│   └─ 기타헌금
└─ 기타 수입
    ├─ 이월금          (연 마감 때 자동으로 생김)
    ├─ 교회보조금
    ├─ 이자수입
    └─ 기타
```

항목마다 가진 설정: `is_offering`(헌금 입력 화면에 나옴), `named`(이름을 적는 헌금인가 — 주일헌금은 보통 무기명 합계), `receiptable`(기부금 영수증에 포함), `fund_id`(들어갈 회계), `needs_unit`·`needs_purpose`(부서·목적을 함께 받음), `is_active`.
쓴 적이 있는 항목은 지우지 못하고 '쓰지 않음'으로만 바꾼다.

### 5.3 지출 분류 = 재정 단위 × 예산 항목

```
지출 (2026 회계연도)
├─ 예배위원회                      ← fm_units (kind=위원회, 교적 조직표에서 가져옴)
│   ├─ 예배부                      ← fm_units (kind=부서)
│   │   ├─ 예배 준비비   1,200,000  ← fm_budget_items (항목·예산액·산출 근거)
│   │   └─ 성찬 준비비     400,000
│   └─ 찬양대 …
├─ 교육위원회
│   ├─ 유치부 …
│   └─ 중고등부 …
├─ …
├─ 공통·기타 지출                   ← fm_units (kind=기타, 교적 조직표에 없는 단위)
│   ├─ 사례비 · 공과금 · 차입금 상환 …
└─ 예비비                          ← fm_units (kind=예비비)
```

- **재정 단위**(`fm_units`): 회계연도마다 한 벌. 새해에 "교적 조직표에서 가져오기" 또는 "작년 것 복사"로 만든 뒤 고친다. `cm_org_unit_id` 로 교적의 부서와 이어 두되 이름은 따로 적어 둔다
- **예산 항목**(`fm_budget_items`): 재정 단위 아래의 지출 항목. 지출은 반드시 어느 예산 항목에서 나가는지 고른다
- 예비비는 직접 쓰지 않고 **예산 변경(전용)** 으로 다른 항목에 옮긴 뒤 쓴다(기록이 남도록)
- 교회 전체를 가로지르는 성격별 통계(인건비·행사비·비품 …)가 필요하면 예산 항목에 `nature`(성격) 꼬리표를 붙여 결산서를 두 가지로 볼 수 있게 한다(선택)

## 6. 헌금

### 6.1 헌금자 (`fm_donors`)

헌금을 한 번이라도 적은 사람마다 한 줄. 교인이면 `person_id` 로 교적과 이어지고(한 교인에 한 줄), 교인이 아닌 사람·단체는 `person_id` 없이 이름만 가진다.

| 열 | 설명 |
|---|---|
| `person_id` | 교적 교인. 비교인·단체는 NULL |
| `name` | 이름 스냅숏 (교적에서 지워져도 남음) |
| `donor_no` | 헌금자 번호(봉투 번호). 쓰는 교회만 |
| `rrn_enc` | 주민등록번호 — **`rrn_mode` 가 '보관'인 교회에서만** 암호화 저장, 영수증에만 사용 (11.2) |
| `receipt_to_donor_id` | 영수증 합산 대상(예: 배우자·자녀 헌금을 세대주 영수증에). 비면 본인 명의 |
| `receipt_address` | 영수증 주소. 비면 교적의 주소 |

교인을 헌금 입력에서 처음 고르면 서버가 헌금자 줄을 자동으로 만든다. 비교인이 나중에 등록하면 '교인과 연결'로 합친다.

### 6.2 입력 흐름

```
주일 헌금 계수 → [헌금 묶음 만들기: 날짜·구분] → 종류별로 이름·금액 입력
   → 종류별 입력 합계 ↔ 실제 센 금액 대조 → [마감] → 장부에 수입으로 올라감
```

- **헌금 묶음**(`fm_offering_batches`): 날짜 + 구분(주일·수요·새벽·절기·계좌이체분 등). 상태: 입력 중 → 마감. 계수 위원 이름, 종류별 계수 금액을 함께 적는다
- **헌금 줄**(`fm_offerings`): 묶음, 수입 항목, 헌금자(무명이면 NULL), 금액, 받은 방법(현금·계좌이체·온라인), 부서/목적, 메모
- **빠른 입력**: 헌금 종류를 고르고 → 이름 몇 글자(초성 검색 포함) → 금액 → Enter 로 다음 줄. 마우스 없이 끝낸다
  - 동명이인은 `홍길동 A (1975 · 3구역)` 처럼 출생 연도와 소그룹을 붙여 구분한다
  - 헌금자 번호를 쓰는 교회는 번호만 쳐도 된다
  - 부부 공동 헌금(○○○·○○○)은 한 사람 앞으로 적고 메모에 남기거나, 합산 설정으로 영수증에서 합친다
  - 무기명 헌금(주일헌금 등)은 이름 없이 합계 한 줄
- **대조**: 종류별 "입력 합계 / 계수 금액 / 차이"를 늘 보여 주고, 차이가 있으면 마감할 때 사유를 적게 한다
- **마감하면** 묶음의 헌금을 수입 항목·계좌별로 묶어 장부(`fm_transactions`)에 수입 거래로 올린다. 장부에는 합계만 올라가고 개인별 내역은 헌금 표에만 있다
- 마감 뒤 고치기는 재정 담당만: 묶음을 '다시 열기'(사유 기록) → 수정 → 다시 마감. 월 마감이 끝난 달은 열 수 없다
- 계좌이체 헌금: v1 은 통장 내역을 보고 직접 입력. 은행 거래내역 엑셀을 올려 이름을 맞추는 기능은 확장 단계

### 6.3 헌금에서 나오는 것

- 주간 헌금 보고(종류별 건수·합계, 지난주·작년 같은 주 비교)
- 주보용 헌금자 명단(종류별 이름, 금액 없이. 싣지 않을 사람 표시 가능)
- 개인별 헌금 내역(기간·종류별) — 개인별 헌금 열람 권한자만, 열 때마다 접속 기록
- 헌금 통계(월별·종류별 추이, 헌금자 수) — 합계만이라 열람 역할도 볼 수 있음

## 7. 예산과 장부

### 7.1 예산

- **지출 예산**: 재정 단위 › 예산 항목 › 금액·산출 근거. **수입 예산**: 수입 항목별 금액(`fm_income_budgets`)
- 상태: 편성 중 → **확정**(공동의회 통과일을 적음). 확정 뒤에는 직접 고치지 못하고 **예산 변경**(`fm_budget_changes`: 추경·전용, 어디서 어디로 얼마, 사유, 승인 근거)으로만 바꾼다. 현재 예산 = 처음 예산 + 변경 합계
- 집행 현황: 항목마다 `예산 / 집행(지급 완료) / 결재 중 / 남은 금액 / 집행률`. 결의서를 쓸 때 남은 금액을 보여 주고, 넘으면 경고 또는 차단(설정)
- 확장: 각 부서가 내년 예산 요구서를 온라인으로 내고 재정위원회가 조정하는 흐름

### 7.2 장부 (`fm_transactions`)

모든 돈의 움직임은 이 표 한 곳에 모인다.

| 종류 | 만들어지는 곳 |
|---|---|
| 수입 | 헌금 묶음 마감(자동), 기타 수입 직접 등록 |
| 지출 | 지출결의서 지급 처리(자동), 재정 담당의 직접 지출 등록 |
| 이체 | 계좌 사이 옮김 |
| 이월 | 연 마감(자동) |

주요 열: 회계연도, 날짜, 종류, 회계, 계좌(이체는 받는 계좌도), 수입 항목 또는 재정 단위·예산 항목, 금액(원 단위 정수 `BIGINT`), 적요, 거래처, 출처(`source`: 직접·헌금 묶음·결의서·이월)와 출처 id, 취소 여부·사유, 등록자·시간.

- **지우지 않는다**: 잘못 적은 것은 '취소'(사유 필수)하고 새로 적는다. 취소한 줄도 장부에 줄 그어 남는다
- **직접 지출 등록**: 자동이체 공과금, 사례비처럼 매번 결재를 올리지 않는 지출은 재정 담당이 바로 등록한다. **어떤 예산 항목이 직접 등록 가능한지는 재정 관리자가 설정 화면(관리자 › 결재 규칙·설정 › 직접 지출)에서 항목마다 지정한다.** 지정하지 않은 항목은 반드시 지출결의서를 거친다
  - 항목마다: 직접 등록 허용 스위치, **건당 한도**(비우면 한도 없음). 공통 설정: 등록할 수 있는 역할(재정 담당 / 재정 담당·재정위원장), 한 달 직접 지출 총 한도(선택), 증빙 필수 여부, 월 마감 때 재정위원장 확인 필수 여부
  - 한도를 넘는 금액은 서버가 거절하고 지출결의서를 쓰라고 안내한다. 직접 등록분은 재정위원장이 월 마감 때 한꺼번에 확인한다
  - 허용 설정을 바꾸는 것은 수정 기록에 남고, 이미 등록된 건에는 영향이 없다
- 자주 쓰는 정기 지출은 '지난달 것 불러오기'로 반복 입력을 줄인다

### 7.3 마감

- **월 마감**(`fm_closings`): 계좌별 장부 잔액과 실제 잔액(통장·현금)을 대조해 적고 재정위원장이 승인. 마감한 달의 헌금·거래는 고칠 수 없고, 고치려면 그 달 이후에 정정 거래를 낸다. 마감 풀기는 재정위원장만(기록 남김)
- **연 마감**: 12개 달이 모두 마감되면 결산을 확정하고, 회계·계좌별 남은 돈을 새 회계연도의 '이월금' 수입으로 자동 등록한다

## 8. 지출결의서와 전자결재

### 8.1 흐름

```
부서 회계        부서장         위원장        재정위원장       재정 담당
 [기안] ──상신──▶ [결재] ─────▶ [결재] ─────▶ [결재] ──────▶ [지급 처리] → 장부에 지출
   ▲               │반려          │반려          │반려
   └───────────────┴──────────────┴──────────────┘   (사유와 함께 기안자에게)
```

상태: `작성 중` → `결재 중` → `결재 완료` → `지급 완료` / 옆길: `반려`(고쳐서 다시 상신), `회수`(첫 결재 전 기안자가 되가져옴), `취소`

### 8.2 결의서의 내용

- **머리**(`fm_vouchers`): 문서 번호(`2026-0153`, 상신할 때 서버가 매김), 회계연도, 재정 단위, 기안자, 제목, 지출 사유, 합계, 지급 희망일
- **지급 방법**: 계좌이체(은행·계좌번호·예금주) / 법인카드 사용분 / 현금 / **먼저 쓰고 청구**(개인이 지출한 것을 돌려받음: 받을 사람 계좌)
- **내역**(`fm_voucher_items`): 예산 항목, 적요, 금액. 한 결의서에 여러 줄(같은 재정 단위 안에서)
- **증빙**(`fm_voucher_files`): 영수증·견적서 사진이나 PDF. 휴대폰에서 바로 찍어 올린다. 증빙 없이 올리면 사유를 적게 한다
- 쓰는 동안 예산 항목의 남은 금액과 올해 그 항목의 지출 목록을 옆에 보여 준다

### 8.3 결재선

상신하는 순간 서버가 결재선을 만들어 `fm_approval_steps` 에 **사람 이름과 함께 고정**한다(나중에 담당자가 바뀌어도 진행 중인 문서는 흔들리지 않게).

**결재 규칙은 금액 구간표(`fm_approval_rules`)로 정한다.** 구간마다 단계 목록을 가지고, 단계는 `결재`(통과해야 다음으로) 또는 `확인`(사후 확인: 지급을 막지 않고 나중에 확인 표시만) 중 하나다. 상신할 때 결의서 합계가 속한 구간의 규칙을 서버가 적용하고, 기안 화면에서 결재선 미리보기를 보여 준다.

| 구간 (합계 기준) | 단계 | 비고 |
|---|---|---|
| 소액 (A원 이하) | 부서장 → 위원장 → 재정위원장(`확인`) | **전결**: 재정위원장은 지급을 막지 않고 월 마감 때 '미확인 목록'에서 일괄 확인 |
| 일반 (A원 초과 ~ B원 미만) | 부서장 → 위원장 → 재정위원장 | 기본 |
| 고액 (B원 이상) | 부서장 → 위원장 → 재정위원장 → **담임목사** | 담임목사가 최종 결재 |
| 추가 조건 (구간과 별개로 더해짐) | 예산 초과 상신·예비비 사용이면 재정위원장 뒤에 담임목사 단계 추가(이미 있으면 그대로) | |

- **A, B 금액은 교회가 설정**한다(설치 때 비워 두고 설정 화면에서 입력, 구간 수도 늘릴 수 있음). 이 문서의 구간 이름은 예시이며 기본 금액을 정해 두지 않는다
- 위원회 직속·부서 없는 지출, 담임목사 개인 관련 지출 등은 `kind` 별로 다른 규칙표를 둘 수 있다(예: 사례비·목회활동비는 재정위원장 → 당회 서기)
- 담임목사 단계는 `담임목사` 역할을 가진 사람이 맡고, 부재 시 대리 결재(`fm_delegations`)를 쓴다
- 규칙을 바꿔도 **이미 상신된 문서의 결재선은 바뀌지 않는다**(상신 때 고정)

예외 처리 규칙:

| 경우 | 처리 |
|---|---|
| 위원회 직속 지출(부서 없음) | 부서장 단계 없이 위원장부터 |
| 같은 사람이 연달아 두 단계(부서장 = 위원장) | 한 번 결재로 두 단계 처리 |
| 기안자가 결재자이기도 함(회계 = 부서장) | 그 단계는 '기안자 본인'으로 표시하고 넘어가되, **기안자가 아닌 사람의 결재가 최소 한 번** 있어야 완료 |
| 재정위원장이 자기 부서 기안 | 다음 차례 결재자(설정: 재정부장 또는 담임목사)가 최종 결재 |
| 담임목사가 기안·결재 당사자(담임목사 직접 지출 등) | 담임목사 단계를 건너뛰지 않고 규칙표의 대체 결재자(예: 당회 서기)로 바꾼다 |
| 담당자가 지정되지 않음 | 상신을 막고 "○○부 부서장이 지정되지 않았습니다" 안내 |
| 결재자 부재 | 관리자가 기간을 정해 **대리 결재자**를 지정(`fm_delegations`). 결재 기록에 '대결'로 남음 |

### 8.4 결재 동작과 기록

- 결재자는 로그인하면 **'내 결재함'**(대기·완료·반려)을 본다. 결재·반려 모두 의견을 적을 수 있고 반려는 사유 필수
- 결재할 때 비밀번호를 다시 확인하고, 결재 시각·결재자 계정·접속 주소와 함께 **그 순간 결의서 내용의 해시**(`content_hash`)를 저장한다. 상신 뒤에는 내용을 고칠 수 없고(고치려면 회수·반려 후 재상신, 결재는 처음부터), 해시로 "결재 뒤 바뀌지 않았음"을 확인할 수 있다
- 알림: v1 은 화면의 결재 대기 건수(로그인 첫 화면·메뉴 배지). 확장 단계에서 문자(솔라피)·이메일 알림
- **지급 처리**(재정 담당): 결재 완료 문서 목록 → 지급일·출금 계좌를 적고 '지급 완료' → 내역 줄마다 장부에 지출 거래가 생기고 결의서와 서로 이어진다. 여러 건을 골라 '이체 목록'(은행·계좌·예금주·금액)으로 내려받을 수 있다
- 지급 뒤 잘못을 발견하면 결의서를 지우지 않고 장부에서 정정 거래를 내고 결의서에 메모를 남긴다
- **출력**: 지출결의서 한 장(결재란에 이름·결재 일시·'전자결재' 표시, 증빙 사진은 뒷장). 감사 때는 기간·부서별로 묶어 한 번에 PDF

## 10. 기부금 영수증

- **대상 금액**: 헌금자별, 과세 연도(1.1~12.31, 회계연도 설정과 무관), `receiptable` 인 수입 항목의 마감된 헌금 합계
- **합산**: 헌금자의 `receipt_to_donor_id` 설정에 따라 가족 헌금을 한 사람 명의로 묶을 수 있다. 세대 정보(`cm_households`)로 "같은 세대" 제안만 하고, 묶을지는 사람이 정한다
- **서식**: 소득세법 시행규칙의 기부금 영수증 서식에 맞춘다 — 기부자(성명·주민등록번호·주소), 기부금 단체(교회 이름·고유번호·소재지), 기부 내용(유형·코드·구분·연월·내용·금액), 발급일, 직인. 내용 줄은 월별 합계 또는 연간 합계 한 줄(설정)
- **발급**: 한 사람씩, 또는 그 해 전체를 한꺼번에(미리보기 → 발급 → PDF 한 묶음·인쇄). 발급 번호는 서버가 거래 안에서 매긴다(`fm_meta.receipt_seq_<연도>`)
- **발급 대장**(`fm_receipts`): 번호, 헌금자, 연도, 금액, 발급일, 발급자, 그리고 **발급 당시의 내용 전체**(이름·주소·줄별 금액을 JSON 스냅숏). 다시 뽑으면 같은 번호의 재발급으로 기록한다. 발급 뒤 헌금이 정정되어 금액이 달라지면 '금액 변동'으로 알리고 정정 발급(이전 것 무효 표시)한다
- **세무서 제출용**: 기부자별 발급명세, 연간 발급 합계 자료를 엑셀로 낸다
- 확장: 교인이 직접 로그인해 자기 영수증을 받는 화면, 홈택스 연말정산 간소화 자료

> 서식 번호·기부금 구분 코드(종교단체 41)·발급명세 보관 기간·합계표 제출 기한은 구현 전에 그 해 기준으로 다시 확인한다. 세법은 자주 바뀐다.

### 11.2 주민등록번호

**교회가 두 방식 중 하나를 고른다** (`settings.rrn_mode`). 설치 마법사에서 처음 고르고, 설정에서 바꿀 수 있다. 기본값은 정해 두지 않고 설치 때 반드시 고르게 한다.

| | **A. 암호화 보관** | **B. 미보관** |
|---|---|---|
| 번호 입력 | 헌금자 화면에서 입력 | 입력칸이 아예 없다 |
| 저장 | AES-256-GCM 으로 `donors.rrn_enc` 에. 열쇠는 `data/config.php` 에 두고 **백업 파일에는 넣지 않는다**(DB 백업만 새어서는 풀 수 없게). 설치 때 열쇠를 따로 적어 보관하라고 안내 | 어디에도 저장하지 않는다 |
| 영수증 | 서버가 풀어 넣음. 풀 때마다 접속 기록 | 생년월일 앞 6자리까지만 찍고 뒷자리는 비워, 기부자가 손으로 적게 한다 |
| 발급 대장 스냅숏 | 마스킹한 값만 | 번호 없음 |
| 화면 표시 | 앞 6자리와 `*` | — |
| 정리 | 마지막 헌금 뒤 일정 기간(설정, 기본 5년)이 지난 헌금자의 번호는 자동으로 지움 | — |

- **A → B 로 바꿀 때**: 저장된 번호를 모두 지울지 확인하고(되돌릴 수 없음) 지운 뒤 모드를 바꾼다
- **B → A 로 바꿀 때**: 열쇠를 새로 만들어 안내하고, 번호는 그 뒤 헌금자별로 입력한다
- B 방식은 영수증을 받는 교인이 번호를 직접 적어야 하므로 안내 문구를 서식 아래에 넣는다. 세무 처리 요건(영수증에 번호가 꼭 필요한지, 발급명세 보관 방식)은 구현 전에 그 해 기준으로 확인한다

### 11.3 지켜야 할 규칙 (서버가 거래 안에서 확인)

- 마감된 달에 속한 헌금·거래는 만들거나 고칠 수 없다
- 결의서 합계 = 내역 줄의 합. 내역의 예산 항목은 모두 그 결의서의 재정 단위에 속한다
- 지급 완료는 결재 완료 상태에서만, 한 번만. 지급과 장부 등록은 한 거래로
- 헌금 묶음 마감과 장부 등록, 영수증 번호 매기기와 대장 기록도 각각 한 거래로
- 결의서 상태를 바꾸는 요청은 `rev` 를 함께 보내고, 서버의 값과 다르면 거절(두 사람이 동시에 처리하는 것 방지)

## 13. 보안·운영 점검표

- [ ] 로그인하지 않으면 API 전체가 401. 모든 경로가 권한 확인 함수(`require_role`, `require_unit_role`, `require_donor_view`)를 거친다
- [ ] 통합 로그인: 교적 계정이 `사용`이고 재정 `fm_access` 도 `사용`일 때만 세션 발급. 교적의 정지·비밀번호 변경(`session_epoch`)이 재정 세션에도 즉시 반영된다. 재정은 `cm_users` 에 쓰지 않는다(입장권 삭제만 예외). 응답에 비밀번호 해시를 넣지 않는다
- [ ] 입장권(SSO): 무작위 값의 해시만 저장, 30초 유효, 한 번 쓰면 삭제, 같은 사이트에서 온 요청만 받는다
- [ ] 개인별 헌금 열람 스위치는 담임목사·재정 담당·재정위원장·지정한 감사에게만 켤 수 있고, 켜고 끄는 것은 수정 기록에 남는다
- [ ] 개인별 헌금·주민번호가 들어간 응답은 권한이 없으면 만들지도 않는다. 보고서 API 는 합계만 낸다
- [ ] 부서 범위 확인은 서버에서: 결의서·예산 현황 요청마다 그 사람의 조직 역할을 다시 계산한다
- [ ] 결재 권한은 결재선에 고정된 사람(또는 유효한 대리)인지, 지금이 그 사람 차례인지 확인한다
- [ ] 중요 동작 전 비밀번호 재확인, 결재 내용 해시 저장
- [ ] 금액·합계·번호는 서버 계산. 음수·0·터무니없는 금액 검사
- [ ] 증빙 파일: 종류 검사(그림·PDF 만), 그림은 다시 그려 저장, 무작위 이름, `data/` 안에 두고 PHP 로만 내려줌
- [ ] 접속 기록·수정 기록은 화면에서 지울 수 없다. 보관 기간은 설정(기본 5년)
- [ ] 백업: 교적과 같은 한 파일 형식(gzip 줄 단위 JSON + 증빙 그림), 자동 백업, 되살리기 전 자동 보관. 주민번호 열쇠는 백업에 넣지 않는다
- [ ] 체험(샘플) 자료: 가짜 헌금·결의서를 넣었다가 한 번에 지우는 기능(교적의 `is_sample` 방식). 교적이 샘플 상태일 때만 허용
- [ ] 교적 연결 점검: 교적에 없는 `person_id`(끊어진 연결), 이름이 달라진 사람, 조직표와 다른 담당자를 한 화면에서 알려 준다
