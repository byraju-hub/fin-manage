# fin-manage
교회 재정 관리 시스템

헌금(개인별 기록)과 기부금 영수증, 예산, 장부, 지출결의서 전자결재, 월·연 마감까지 다루는 교회 재정 프로그램입니다. 교적 관리 [ch-manage](https://github.com/byraju-hub/ch-manage)(`cm_`), 부서 관리 [dep-manage](https://github.com/byraju-hub/dep-manage)(`dm_`)와 같은 호스팅 계정·같은 DB에 설치해 함께 쓰며, 표 이름 접두어는 `fm_` 입니다. **교적 계정으로 로그인**하고, 재정 사용을 승인받은 사람만 쓸 수 있습니다. 무료로 배포합니다.

> **상태: v0.1.0 (개발 중).** 설계의 M0~M6와 M7 일부가 구현되어 로컬 시험을 통과했고, 카페24 시험 사이트에도 올려 두었습니다. 아직 실제 교회에서 운영한 적은 없으니 **샘플 자료로 먼저 연습**해 보세요. 남은 일은 아래 "아직 없는 것"을 보세요.

- 사용 설명서: [docs/manual.md](docs/manual.md)
- 구조 설계: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- 디자인 시안: [design/index.html](design/index.html) (브라우저로 열면 됩니다. 이름과 금액은 모두 예시)

## 아직 없는 것

- 교적 화면의 '재정 열기' 버튼·교적 문서 화면 안내 (ch-manage 수정이 필요한 M1-b)
- 자동 백업 일정 (카페24에는 cron이 없어 수동 백업만), 증빙 사진은 백업 파일에 들어가지 않음(서버 `data/vouchers` 별도 보관)
- 문자·이메일 결재 알림, 예산 요구서, 전도금·품의, 교인 본인 영수증 조회, 은행 거래내역 엑셀 자동 대조
- 세법 서식·코드는 해마다 확인이 필요합니다. 운영 전에 세무 담당자와 영수증 서식을 점검하세요.

## 구조

```
src/      SvelteKit 정적 앱 (adapter-static, Svelte 5). 서버의 PHP API(/api/v1)와 이야기합니다.
server/   프레임워크 없는 PHP API(api/controllers), 설치 마법사(install), 데이터베이스 구조(migrations)
docs/     설계 문서·사용 설명서      design/  화면 시안(정적 HTML)      tests/  통합 시험
```

## 설치해서 쓰기

[Releases](https://github.com/byraju-hub/fin-manage/releases)에서 `fin-manage-vX.Y.Z.zip` 을 받아 압축을 풀고, 안의 내용을 호스팅 사이트 폴더(예: `www/fm`)에 올린 뒤 `/install/` 을 엽니다. **교적 관리(ch-manage)가 같은 데이터베이스에 먼저 설치되어 있어야 합니다.**

새 버전으로 올릴 때는 파일을 덮어쓴 뒤 `/install/` 을 한 번 열어 데이터베이스 변경과 마무리를 적용합니다. (`data/config.php` 는 zip 에 없으므로 덮어써지지 않습니다.)

서버 요구사항: PHP 8.1 이상 (`pdo_mysql`·`mbstring` 필요, `openssl`·`gd` 권장), MariaDB 10.x / MySQL, Apache mod_rewrite, ch-manage v0.1.0 이상(구조 번호 6 이상). 호스팅의 요청 크기 제한(128KB)에 맞춰 사진·백업 업로드는 조각으로 나눠 보냅니다.

설치 직후 순서: 재정 사용 승인(역할 지정) → 기준 자료(회계연도·계좌) → 재정 단위(교적 조직표 가져오기·담당자 지정) → 결재 규칙(금액 구간) → 예산. 연습은 설정 › 백업 › **샘플 자료 올리기**로 시작할 수 있습니다.

## 개발

교적이 같은 DB에 설치되어 있어야 하므로, 개발용 DB에 ch-manage를 먼저 설치하고 샘플 데이터를 넣어 둡니다.

```
npm install
php -S 127.0.0.1:8091 -t server server/dev-router.php   # PHP API + 설치 마법사 (http://127.0.0.1:8091/install/)
npm run dev                                              # 화면 (http://127.0.0.1:5174) — /api 는 위 PHP 서버로 넘어갑니다
npm run check                                            # 화면 타입 검사
MSYS_NO_PATHCONV=1 bash scripts/build-release.sh         # 배포용 zip (dist/)
```

통합 시험 (개발 DB와 위 PHP 서버가 떠 있어야 하고, 시험 계정·자료는 시험이 만들고 지웁니다):

```
PYTHONIOENCODING=utf-8 python tests/auth_flow.py   # 통합 로그인
PYTHONIOENCODING=utf-8 python tests/m1_flow.py     # 승인·역할·기준 자료·재정 단위     (m2~m7: 헌금·예산/장부·결재·영수증·마감/백업·통장 맞추기)
PYTHONIOENCODING=utf-8 python tests/m8_import.py   # 기존 자료 가져오기      (m9_sample.py: 샘플 올리기/지우기)
```

지킬 것:
- 내부 링크는 `href="/…"` 가 아니라 `hrefTo('/…')` (`src/lib/paths.ts`)를 거칩니다. 서브폴더에 올려도 주소가 맞아야 하기 때문입니다.
- PHP에서 사이트 폴더 주소는 `dirname()` 을 직접 쓰지 말고 `fm_site_base()` / `fm_dirname()` 을 씁니다. (Windows 의 PHP 는 `dirname('/api')` 가 `\` 를 돌려줘 쿠키 경로가 깨집니다.)
- 교적(`cm_`) 표는 읽기만 합니다. 교인·사용자는 `person_id`/`cm_user_id` 로만 가리키고 외래키를 걸지 않으며, 이름을 함께 적어 둡니다.
- 돈은 원 단위 정수, 장부는 지우지 않고 취소(사유 필수), 돈이 오가는 곳은 `tx()` 한 묶음으로 처리합니다. 데이터베이스 구조를 바꿀 때는 기존 마이그레이션을 고치지 말고 새 번호 파일을 추가합니다.
